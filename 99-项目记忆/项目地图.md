# 项目地图

## 项目一句话

TrustMap Prototype 是论文设计的可运行开源实现：在独立 Geth EVM 链之间，用链上 TrustRoot 和链下 MapNode/TrustView 复用已验证跨链依赖。

## 当前研究与工程目标

- 配置和脚本支持 2 至 21 条独立 Geth developer chain。
- 默认以 3 链完成 DirectPlan 与递归 PathPlan 端到端验证。
- 一条链对应一个 MapNode，MapNode 使用真实 RPC、事件订阅、P2P、持久化和交易提交。
- 论文是规范来源，所有关键机制建立实现与测试追踪。

## 核心目录

- `docs/superpowers/specs/`：已经确认的设计规格。
- `99-项目记忆/`：当前路线、决策和交接。
- `Mapnode/`、`contracts/`、`data/`、`scripts/`、`tests/`：用户预建的空目录；最终布局以已确认设计为准。
- 未来 `cmd/`、`internal/`：Go MapNode 与 CLI。
- 未来 `contracts/src/`、`contracts/test/`：Solidity/Foundry 合约与测试。
- 未来 `configs/`、`docker/`、`runtime/`：配置、容器包装和 Git 忽略的运行时数据。

## 论文主线速查

- Overview：两层架构和端到端工作流。
- TrustMap：TrustRoot、递归 membership verification、lazy update、TrustView、成本规划和 fallback。
- Security Analysis：MapNode/TrustView 不进入链上接受信任根。
- Implementation and Evaluation：Solidity 合约、链下 MapNode、Geth 测试网络和路径成本指标。

## 实现参考速查

- `TrustMap-ETH/contracts/TrustMap/TrustMap.sol`：增量 Merkle 和旧验证实现参考。
- `TrustMap-ETH/Trustmap-simulate/`、`Dune/trustmap_sim*.py`：路径规划与实验成本模型参考。
- `TrustMap-ETH` 历史 `TrustMap4` 分支 `relayer/`：旧链下分层尝试；存在大量 TODO 和全局模拟状态，不能直接作为真实 MapNode。

## Git 与子仓库

- 当前仓库是独立 Git 仓库。
- `TrustMap-ETH` 和论文仓库不是本仓库子模块，不得由本项目任务修改。

## 项目内工作流

1. 新对话先读项目记忆和当前设计规格。
2. 设计变更必须先更新规格与论文追踪矩阵。
3. 实现按详细计划拆分，小提交、测试先行。
4. 合并前检查未提交 runtime、私钥、keystore 或链数据。
